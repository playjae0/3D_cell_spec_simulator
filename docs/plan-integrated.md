각 내부 단위마다 의미 있는 검증 후 커밋한다. 생성 계약 파일은 단일 사전/계약에서 재생성한다. 실제 제품값은 추정하지 않는다. 사용자 요청에 따라 화면 실행/권한 요청은 개발·자동 검사 이후 최종 검증 단계에 한정한다.

필수 검증: 원점 변경 −1→−11과 프레임 회전/고정 앵커 변경의 기존 개정 샘플 차단, 카메라 변경 허용, S3/S4 실런트·테이프 독립과 원본 불변, 공정별 검사 세트 중복 방지, 프리셋 왕복, A/B 비교의 부재/참조 소실/기준 불일치, 보관함 중복·충돌·참조 매핑·저장 실패.

단위 1: 제공 재현에서 기존 guard 통과, −1→−11, datum 차이 0을 확인했다. 검사 의미에는 관련 제품/측정 공정·모드·축·참조·데이텀·앵커·목표/공차/조건을 포함하고 표시·카메라는 제외했다. S3 실런트는 기존 CAD 재사용. 신규 intake 1.1은 S3 존재/부재 확인을 요구하며, 기존 1.0의 미입력 S3는 null을 보존하고 실런트를 생성하지 않는 미확정 호환 경로와 경고를 둔다. 부재로 저장하지 않는다. 기존 1.0 양식은 유지하고 새 1.1 양식/조건/예제는 generator로 만든다.

단위 2: 검사 선택/작성 가이드, 등록 평탄면의 수치 위치 입력, 중복 없는 현재 공정 검사 세트, 명시적인 측정 조건, 검사 보기의 소유 모델/개정/공정과 참조 검증을 추가했다. 공정 전환이 검사 세트를 자동 추가하지 않으며 추가 버튼을 사용한다. 표시만 바뀌면 실측 개정을 강제하지 않는다. 참조 소실/공정 미등장/앵커 범위 이탈을 오류 코드로 구분하도록 기존 2개 검사 기대값을 확장했다. JS 49개 및 개발 웹 빌드 통과. 최종 UI 확인은 마지막에 수행한다.

단위 3: A/B는 선택 시의 스냅샷과 별도 CAD 결과를 사용하고 비교 결과를 활성 작업에 적용하는 경로가 없다. product+stage 캐시(최대 8개), 단일 직렬 CAD 실행, 취소/지연 무효화를 추가했다. 전역 프레임을 이동시키지 않고 카메라·단면만 동기화한다. 저장 검사 기준과 공통 전역 기준을 구분하며, 서로 다른 측정 위치/모드는 공통 프레임에서도 직접 비교하지 않는다. JS 51개와 웹 빌드 통과.

단위 4: 병합은 순수 후보 계획→사용자 충돌 선택→저장 성공 후 메모리 교체다. 개정/샘플/초안의 중복을 구분하고 새 모델 또는 새 개정 가지 복사 시 부모·샘플·검사 보기의 소유 참조를 함께 매핑한다. 손상 보관함은 쓰기를 잠그고 원본 다운로드 및 별도 복구 키 보존 경로를 제공한다. 개정 부모 누락/순환을 검사한다. JS 57개와 개발 웹 빌드 통과.
