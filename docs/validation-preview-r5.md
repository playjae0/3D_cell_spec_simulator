# R5 프리뷰 검증 기록

R4 기준 `37c668e`, 배포 기록의 소스 커밋 `74bfa071644a267aef535e755d344cbfcd0ffae1`. Linux, Node 24.22.1, Python 3.12, CadQuery 2.7.0, Chromium 156에서 확인했다.

## 실행과 조작

1. Node와 CadQuery를 설치한 저장소에서 `npm run build:preview`를 실행한다. 프로젝트의 `.venv` 또는 PATH의 Python을 사용하며 `POUCH_PYTHON`으로 지정할 수 있다. 빌드는 빈 loopback 포트에 CAD 서버를 기동하고 기록을 검증한 뒤 해당 서버를 종료한다.
2. `python -m http.server 8080 --directory dist-preview`와 `http://127.0.0.1:8080/`으로 정적 화면을 연다. 서브디렉터리에서는 끝에 `/` 또는 `index.html`을 붙인다.
3. **기본 가상 예제 열기**, **가상 파우치 공정 예제 열기**, **요소기술 → R4 가상 예제 열기** 중 하나를 선택하고 **공정 상태**를 전환한다. **기록 형상 비교**에서 A/B 모델과 공정을 고른다. 편집과 저장은 기존 `scripts/start.*`로 실행한 로컬 앱에서 한다.

## 실제 기록과 바이트 대조

공개 예제별 20개, 합계 60개 조합에 실제 HTTP 요청을 하고 다시 요청했다. 아래 원문은 최초 응답 전체, 정규화는 요청용 최상위 필드만 제거한 원문이다. gzip은 설계마다 정규화 원문을 이어 압축한 값과 사전 파일을 압축한 값의 비교이며 배포 파일은 JSON이다.

| 설계 | 200 / 422 | 서버 원문 | 정규화 원문 | 중복 제거 파일 | gzip 정규화 → 사전 |
|---|---:|---:|---:|---:|---:|
| 기본 | 7 / 13 | 2,005,279 B | 2,004,576 B | 1,072,572 B | 354,203 → 167,571 B |
| 파우치 | 12 / 8 | 5,313,988 B | 5,312,996 B | 2,456,745 B | 897,828 → 354,285 B |
| R4 요소기술 | 17 / 3 | 9,270,560 B | 9,269,287 B | 5,098,143 B | 1,478,723 → 662,999 B |
| 합계 | 36 / 24 | 16,589,827 B | 16,586,859 B | 8,627,460 B | 2,730,754 → 1,184,855 B |

복원 60/60과 라이브 재요청 60/60에서 상태 및 원문 바이트가 일치했다. 기본 예제 P0~P4는 `pouchProcess.상세 입력 미확정 · 기존 파우치 값을 자동 변환하지 않습니다`를 그대로 표시한다. 기본·파우치 예제의 R0~R7과 R4 요소기술 예제의 P2/P3/P4도 해당 실제 CAD 거부를 재현한다. R4 요소기술 예제의 R0~R7은 모두 성공했다.

배포 폴더는 **8개, 9,588,003 B**다. 최대 파일은 `preview/process-tooling-r4.json`의 **5,098,143 B**다. 16,000,000 B/511개/256,000,000 B 경계와 각 초과 거부를 검사했다. 실제 디렉터리 순회에서 16,000,000 B 파일이 통과하고 16,000,001 B 파일이 이름과 크기를 표시하며 거부됨을 확인했다. Python 기동 실패 시 빌드는 실패하고 기존 성공 폴더의 매니페스트를 유지했다.

## 브라우저와 회귀 검수

- `/review/r5/` 하위 경로에 배포 폴더만 정적으로 제공했다. Chromium에서 성공 36개와 거부 24개의 공정, 부품 목록 또는 정확한 422 문구를 대조했다. 시작 시 매니페스트와 기본 설계만 요청했고, 선택 후 각각의 다른 설계를 한 번 읽었다. 정적 모드에서 CAD POST는 0건이다.
- 시작 이력 없음, 세 번 전환 후 undo 두 번과 redo 한 번, 422 이후 확정 형상과 redo 유지, 공정별 R4 설정과 설계·저장·STEP·개정 잠금, P2↔P4 양쪽 뷰와 Δ 표를 확인했다. 늦은 설계 파일, 해시 불일치, 누락된 부품 참조 및 기록 없는 일반 빌드 경로를 검사했다. 비교 캐시 사용 후의 미기록 개정과 변경 설계도 거부했다.
- 실제 CAD에 동일 프리뷰 번들을 연결했다. 화면이 라이브 모드로 시작했고 적층 길이 **240→241 mm**가 실제 응답의 외곽 치수에 반영됐다. 비교가 `/api/rebuild`를 두 번 요청했고 프리뷰 파일 요청은 없었다. 브라우저 콘솔 오류는 정적 모드의 최초 `/api/health` 404 한 건을 제외하고 0건이었다.
- `npm test` 79개 통과(R4 76개 + 신규 3개), `python -m unittest discover -s tests -p "*geometry*.py"` 48개 통과. 일반 `npm run build`와 `npm run build:preview` 성공. Vite의 기존 큰 번들 경고가 표시됐다.
- `check_api.py`, `check_process_step.py`, `check_intake_api.mjs`, `check_integrated_api.mjs`, `check_pouch_api.mjs`, R4 `check_tooling_r4.py`를 실행해 통과했다.

재검수는 두 빌드 후 Chromium이 설치된 Python Playwright 환경에서 `python scripts/check_preview_browser.py`로 실행한다. 실시간 우선 검수도 실행하려면 기존 로컬 CAD 서버를 켜고 `--live http://127.0.0.1:8765`를 붙인다. Chromium 실행 파일은 `POUCH_CHROMIUM`으로 지정할 수 있다. Windows와 iPad 실기 및 외부 정적 호스트는 이번 검수에 포함하지 않았다.
