# v1.2 공정 상태와 직접 편집 기준

2026-11-17. 기준 코드: main `2d7b606` (v1.1 PR #2 병합). 최신 사용자 요구사항은 [요청 원문](request-v1.2.txt)이며 v1.1 문서보다 우선한다. 기존 사용자 변경이 없는 별도 worktree에서 작업했다. `cad/proof_pocket.py`와 파우치 포켓/실링/접힘 생성 방식은 보존했다.

## 기존 구현과 차이

|항목|v1.1|v1.2|
|---|---|---|
|포일 폭|rootWidth와 width 사이 폭 수축|극별 foilWidth 하나. Y 중심은 독립. 실제 CAD 단면으로 일정 폭 검증|
|상태|테이프 후/패키징/완성 3개|S0–S4 앞 공정 + 기존 패키징/완성, 총 7개|
|용접|메인 접합 관리 면|가용접과 메인 용접을 별도 ID/영역/측정·스펙으로 분리|
|편집|오른쪽 수동 적용|필드↔형상 연결, 등록 모서리/치수 더블클릭, 터치 선택 후 편집, +/-|
|갱신|수동 재생성|자동 debounce + 수동 모드, 단일 실행/최신 대기 요청, 미확정 가이드|
|구버전 JSON|schemaVersion 2|schemaVersion 3, 폭 선택을 확인하는 명시적 변환|

확정: 낱장 적층형이며 Jellyroll은 적층 전극조립체 반제품의 명칭이다. 권취형을 뜻하지 않는다. 양끝의 양극·음극 데이터는 독립이다. 포일 폭은 뿌리부터 집속까지 일정하며 집속은 두께 방향으로 모인다. Y 편심은 별도 입력이므로 폭 조건으로 중심을 고정하지 않는다. V자/블레이드/S1 특허 형상과 W2/W3 특수 실시예를 사용하지 않는다. 노란 테이프는 확인된 부품이다.

## 상태 정의

|단계 / 저장 ID|표시·적용|사용하지 않는 후속 입력|
|---|---|---|
|S0 `stacked`|적층체 + 일정 폭의 집속 전 포일 포락|집속 높이/R/길이, 모든 용접·리드·테이프·파우치|
|S1 `gathered`|뿌리 분포 → smoothstep 두께 집속 → 유한 평탄 구간|가용접·리드·메인 용접·테이프·파우치|
|S2 `preweld`|집속 포일 + 가용접 관리 면. 극별 preweldLead.included로 리드 선택|메인 리드 입력·메인 용접·테이프·파우치|
|S3 `welded`|메인 리드 + 실제 겹침 + 메인 용접 관리 면, 가용접 ID 유지|테이프/리드 필름·파우치|
|S4 `assembly`|S3 + 부착 테이프 + 예시 리드 필름|파우치|
|S5 `packaged`|기존 파우치 포켓/실링 관리 폭/외곽/추가 여유|완성 접힘|
|S6 `finished`|기존 예시 접힘과 완성 외곽|패키징 추가 여유를 제거하는 기존 가정 유지|

이는 제품 상태 설명 모델이다. 실제 라인의 전체 공정, 절단/트리밍, 장비 구동, 용접 물리 해석을 추가한 것이 아니다. 분포선 9개는 설명용이며 개별 포일 장수나 한 장의 두께를 뜻하지 않는다. 가용접 면은 재료 솔리드/비드/압흔이 아니고 STEP 재료에서 제외한다.

S2 리드 포함 여부는 양극·음극별 명시적 데모 설정이며 기본은 미포함이다. `preweldLead`는 해당 단계의 리드 배치 입력이다. S3의 `lead`와 별도로 저장하여 S3 변경이 S2를 소급 수정하지 않는다. partId는 둘 다 같은 `positive.lead`/`negative.lead`이고 상태별 설계 결과만 다르다. S2 리드 포함을 실제 공정으로 확정하지 않는다.

## 데이텀과 입력의 전달 방향

기존 mm, A=Z0 두께 중앙, B=Y0 폭 중앙, C=X0 길이 중앙을 유지한다. `product.positive`와 `product.negative`는 독립 객체다.

- S0 입력: `tab.foilWidth`, `rootLength`, `rootSpread`, `rootY`, `rootZ` 및 공통 조립체 외곽.
- S1 입력: `gatherDistance`, `gatherY`, `gatherZ`, `thickness`, `edgeR`, `axialShortening`.
- UI의 **집속 후 길이**는 `rootLength − gatherDistance − axialShortening`이다. 해당 길이를 직접 입력하면 `axialShortening`을 역산한다. S0 돌출 길이를 바꾸지 않는다. 같은 자유도를 둘로 구속하지 않는다.
- 집속 거리 편집은 뿌리를 고정하고 집속 완료 단면을 이동한다. 투영 수축이 고정되므로 집속 후 끝 위치는 유지되고 평탄 구간 길이가 달라진다.
- S0 돌출 길이를 바꾸면 S1 이후 평탄 구간 길이/끝과 관련 주석이 따라간다.
- 리드 시작은 집속 완료 단면 기준 바깥 X, 리드 폭/두께/Y 오프셋은 독립, Z는 접촉 면과 탭/리드 두께에서 계산한다. 겹침 길이·폭은 실제 구간 교집합이다.
- 가용접 영역은 집속 포일 평탄부, 메인 용접 영역은 실제 탭–리드 겹침 내부여야 한다. 각각 배열로 여러 영역을 관리하며 ID와 측정 스펙이 독립이다.
- 테이프는 기존 host/face/path 관계를 보존한다. 두께·부착 위치·피복을 편집하면 CAD와 기준이 함께 갱신된다.

**투영 수축은 설명용 포락 모델의 축 방향 차이를 명시한 설계 가정이다. 실제 포일 재료의 호 길이/변형률 보존을 해석하지 않는다. 음의 값도 투영 차이로 기록되며 임의 절단 공정을 뜻하지 않는다.** 이 부분을 실제 포일 변형 계산으로 사용하지 않는다.

## 데이터와 참조

`schemaVersion=3`, `modelVersion=pouch-process-cad-2`. 제품 입력 한 벌과 상태 ID를 저장하고 전체 모델을 공정별 복제하지 않는다. `cad/process.py`가 상태에 필요한 입력만 해석해 임시 CAD 입력을 만든다. 저장 데이터에는 임시 rootWidth/width/length를 쓰지 않는다.

- `positive.tab`, `positive.lead`, `positive.preweld.pre-1`, `positive.joint.main`, `positive.tape.yellow` 등 partId를 유지한다.
- `*.tab.root`, `*.tab.gather`, `*.lead.start`, `*.joint.ID.start` 같은 의미 기준으로 주석을 연결한다. 메시 삼각형 번호를 저장하지 않는다.
- 현재 상태에 아직 없는 등록 기준은 `available:false`다. 치수 카드에 **해당 상태에서 사용 불가**로 나타나며 ID를 유지한다.
- 실제 삭제된 영역/기준은 **참조가 없음 · 재선택 필요**다. 자동 재연결하지 않는다.
- 설계 입력, 파생 CAD/기준점, 검사 목표·공차·실측은 분리한다. 실측 변경은 형상에 반영하지 않는다.
- JSON은 원래 스펙·카메라·단면·표시·주석·표면점과 자동 갱신 설정을 보관한다. 파생 메시를 저장하지 않는다.

v1.1 불러오기에서는 양극/음극 각각 기존 뿌리 폭과 집속 폭을 보여 주고 **뿌리 값 / 집속 값 / 직접 입력** 중 선택한다. 같은 값이어도 선택을 확인한다. 취소 시 현재 프로젝트는 유지된다. 원래 전체 product와 선택 내역은 `migration`에 보존한다. 가용접 데이터는 기존 파일에 없으므로 빈 목록이며 사용자 추가 버튼으로 생성한다. v0.4는 자동 변환하지 않는다.

## 편집과 갱신

`src/data/bindings.js`가 필드 경로, 고정 기준, 영향 부품, 의미 기준, 예상 치수 가이드, 모서리의 입력 후보를 연결한다. [필드 연결표](field-geometry-map-v1.2.md)를 참조한다.

필드 hover/focus는 부품·기준·치수선을 강조한다. 입력 중에는 주황색 **예상 변경**, 계산 뒤에는 확정 CAD 기준을 표시한다. 곡률 입력은 원호 가이드를 표시한다. R이나 길이를 화면 픽셀에서 역산하지 않는다. 3D hover는 이름, click은 선택 고정과 관련 항목 펼침으로 연결된다. 선택 모드는 부품/등록 모서리·R/기준면/기준점으로 나뉜다. 등록 기준 마커는 선택 부품과 모드에 필요한 것만 표시한다.

등록 모서리 또는 표시 치수선 더블클릭은 해당 위치에 편집창을 연다. 입력 하나면 바로 값이 나오고 여러 입력이면 선택한다. 겹침 같은 계산값은 직접 입력하지 않고 원인 입력을 선택한다. Enter 적용, Esc/취소/바깥 클릭은 미적용 취소다. 이동 5px 이상 드래그는 편집 클릭으로 처리하지 않는다. 터치용 **선택 치수 편집** 버튼도 같은 창을 연다. 임의 BRep 모서리 전체의 자동 변수 추론은 지원하지 않는다.

숫자 입력은 기본 550ms debounce다. `src/geometry/queue.js`는 한 요청을 실행하면서 마지막 대기 입력만 유지한다. 새 입력 즉시 revision을 증가시켜 아직 전송 전인 새 입력보다 오래된 응답도 거부한다. 최신 요청이 실패하면 입력 옆과 하단에 원인을 표시하고 마지막 정상 CAD를 유지한다. JSON/STEP 저장은 미적용·계산 중·오류 상태에서 잠긴다. 자동/수동 모드를 선택할 수 있다. 같은 입력에 포커스를 둔 연속 +/-는 한 이력 단위다. 카메라는 CAD 갱신 때 유지하며 맞춤은 명시적 버튼이다.

`/api/health`의 live-cad/schemaVersion/capabilities, `/api/rebuild`의 요청 token/revision/stage를 확인한다. 고정 메시 프리뷰나 구버전 서버를 계산 서버로 취급하지 않는다. 이 경우 편집을 잠그고 연결 필요를 표시한다.

## 후속 파우치 확장 연결점

기존 `product.pouch` → `cad/proof_pocket.py` → `pouch.*` 경계 ID를 보존했다. 향후 내부 조립체 수납 배치, 리드 필름 상대 위치, 실링바 작업면·윤곽, 절단선, 접힘선을 별도 datum/feature로 연결할 수 있다. **SKOn_Sealing_Bar_Handoff.zip은 이번 작업 파일/저장소에서 확인되지 않았다.** 실링바 윤곽 기능을 새로 구현했다고 기록하지 않는다. 현재 sealWidth는 기존의 균일 링 관리 영역이다.

리드 통과부 국부 성형/실링 압축, 실제 주름/포일 변형, 임의 CAD 면/모서리 편집, 임의 곡면 테이프, STEP 가져오기/PMI와 자동 도면은 여전히 미지원이다. 접힘 각도·전개 여유 일부는 가이드와 설계 편집을 지원하지만 각도/전개길이 관리 치수 모드는 별도 확장 대상이다. iPad 터치와 Windows 실기 검증은 아직 수행하지 않았다.
