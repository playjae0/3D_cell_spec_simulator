# v1.3 모델·개정 및 셀 입력 계약

기준 main `3e0f9f8` / PR #3. 사용자가 Claude에서 실행한 전체 프로그램과 동일함을 확인했다. 새 read-only 사이트를 개발 기준으로 삼지 않았다. 기존 v1.2 CAD/7공정/직접 편집/큐/마이그레이션을 유지한다. 이 변경은 2026-11-18(한국시간)에 검증했다.

## 저장 단위

|형식|역할|
|---|---|
|pouch-cell-intake / 1.0|미완성 입력·출처·상태·충돌·검사 정의·표면점. null 유지. CAD 완료와 별개|
|schemaVersion 4 / pouch-process-cad-2|선택 공정에서 검증한 프로젝트. intake, 정규화 product, modelIdentity, 검사 프레임/주석 포함|
|pouch-model-library / 1|모델별 불변 개정, 미완성 drafts, 별도 samples. 브라우저 로컬 보관 + JSON 내보내기|
|schemaVersion 3 및 v2|기존 프로젝트를 계속 읽는다. v2 폭은 기존처럼 양극/음극별 명시적 선택 변환|

schema3는 자동으로 임의 제품값을 바꾸지 않는다. 모델 목록 등록/새 확장점 저장 시 schema4를 쓴다. intake 없이 완성 제품 구조를 가진 schema4도 지원한다. 내부 CAD의 modelVersion은 유지했고 JSON 스키마만 확장했다.

모델을 생성하려면 modelId/name/revision, 확정된 좌표 매핑, 해당 공정 필수값과 근거·검토 상태가 필요하다. 이후 공정만 미입력이면 현재 CAD를 생성할 수 있다. 비활성 형상을 만들기 위해 가상 치수를 대입하지 않는다. Python resolver/build도 S0에서 집속값, S1에서 리드값, 패키징에서 완성 접힘, 완성에서 패키징 추가 여유를 읽지 않도록 분리했다.

## 계약과 검증

`src/intake/contract.js`의 공정/존재/경로 조건이 기준이다. `scripts/generate-intake.mjs`로 빈 양식과 [필수 조건표](intake/required-fields.json)를 생성한다. 테스트가 생성물과 코드 일치를 검사한다. 원본 초안 사전은 참고 자료로만 남겼다. 정식 양식은 `examples/intake/template-1.0.json`을 사용한다. 1.0-draft 파일은 버전 오류를 표시하며 조용히 새 계약으로 간주하지 않는다.

Ajv 8.17.1이 구조를 검사하고 별도 의미 검사가 ID·타입·단위·enum·출처·부품 존재·검토 상태·계산 관계를 확인한다. µm 계열은 mm로 정규화하되 원본 JSON 값을 보존한다. 허용 연산은 unit_scale/sum/difference이며 문자열 eval은 없다. 단위 변경과 치수 의미 변경을 같은 것으로 취급하지 않는다. 임의 전체 길이↔돌출 길이 자동 추론은 하지 않는다.

배열은 polarity/kind/instanceId로 연결하고 parameterId는 `positive.tapes.yellow.width` 같은 영구 ID다. 숫자 배열 인덱스는 화면 편집 시에만 계산한다. 신규 인스턴스는 JSON 검토 화면/양식에서 정의한다. intake 모델의 기존 영역을 제외하면 enabled=false와 확인된 부재를 기록한다. 기존 v1.2 모델의 영역 추가/삭제는 유지한다.

지원되지 않는 필드와 잘못된 값은 오류를 표시하고 원본 초안에 남는다. 표현 불가 요구는 unmappedRequirements로 보존한다. 검사 feature가 없으면 항목을 보존한 채 미연결/재선택 상태로 표시한다. 미래 공정에서만 사용할 수 있는 기준과 삭제된 기준을 구별한다.

## 화면과 원자적 적용

상단 **모델 / 입력 양식** → 신규 모델 / 현재 모델 새 개정 / 다른 모델 복사. 전체/현재 공정 빈 양식을 내려받거나 작성 JSON을 연다. 검토표는 원문 숫자와 단위, 정규화, 필수/미입력/검토 상태를 보여주고 선택 시 기준·출처와 CAD 가이드를 표시한다. JSON 수정 영역에서 모델 식별자·출처·항목을 편집하고 재검증한다. 검토 완료 버튼은 사용자 행동을 reviewLog에 남긴다.

임시 CAD는 별도 뷰어에서 계산한다. 입력/공정 변경·닫기 즉시 응답 토큰을 무효화한다. 실패/취소/늦은 응답은 현재 모델 및 undo 이력을 바꾸지 않는다. **새 모델/개정 적용**은 브라우저 저장 성공 후 한 번만 현재 작업을 교체한다. 같은 개정 덮어쓰기는 거부한다. 현재 작업을 직접 편집한 뒤 **현재 작업 개정 저장**으로 새 개정을 만든다. UI의 REV 숫자는 계산 요청 번호이며 modelRevision과 다르다.

개정 비교는 parameterId로 값·단위·출처 기록 차이를 보여준다. 검사 정의와 데이텀/표면점도 개정 스냅샷에 보관한다. 모델 복사 시 실측은 복사하지 않는다. samples는 sampleId/modelId/modelRevision/itemId/값/mm로 분리된다. 같은 항목에 여러 샘플을 기록해도 CAD를 재계산하지 않는다. 저장된 개정과 작업 사본이 다르면 먼저 새 개정을 저장하도록 안내한다. 기존 단일 실측이 있는 schema3 작업을 모델로 등록하면 legacy-import 샘플로 옮긴다.

## 측정과 참조

- 기존 x/y/z 절댓값, 직선/두께/R 의미를 유지한다.
- signed_coordinate: 검사 프레임 원점에서 A까지 지정 축 부호 좌표. signed_offset: A→B의 지정 축 부호 차이. 예: 뿌리 Y=-1은 −1.000 mm다.
- 측정별 datumId. 모델 A/B/C와 별도로 검사 프레임 이름·원점·XYZ 축을 표시한다. 프레임은 원점 XYZ와 Z 회전을 지원한다. 임의 3축 회전/기준면에서 지그 자동 추론은 미지원.
- relative 표면점은 u/v 비율, fixed_mm은 면 중심 또는 U±/V± 모서리 중점에서 고정 거리다. U/V는 해당 해석 패치 축이며 화면 좌우가 아니다. 범위/라운드 이탈 시 보정하지 않고 무효화한다. 리드/적층체 상하면의 등록 평탄 패치만 지원한다.
- 필드에서 만든 치수에 parameterId와 featureId를 함께 보존한다. 형상 변경 후 기준을 다시 계산하며 표시 메시를 치수 근거로 쓰지 않는다.

## 제한 및 운영

로컬 브라우저 보관함은 동시 사용자 DB가 아니다. 브라우저/포트별로 별도 보관되므로 JSON 백업을 사용한다. 보관함 가져오기는 기존 모델이 비어 있을 때만 허용하며 기존 목록을 조용히 덮어쓰지 않는다. 목록 병합·서버 협업·사용자 인증·자동 백업은 미지원이다. 작업 중인 현재 프로젝트는 JSON 저장으로 백업하며, 브라우저 재실행 후 모델 목록에서 저장 개정을 다시 연다.

현재 모델 등록, 검토·미리보기·적용, 부호 치수와 실측 저장은 브라우저에서 확인했다. 파일 선택을 통한 업로드는 자동화 시간 초과 후 사용자가 권한 요청을 거부했다고 알려 다시 시도하지 않았다. 계약 파싱/변환→실제 API 경로는 별도 자동 검사로 확인했다. 파일 선택 대화상자를 포함한 인수는 사내에서 확인해야 한다. 자세한 결과는 [검증 기록](validation-v1.3.md).

파우치 실링바, 새로운 CAD 엔진, STEP 가져오기/PMI, 도면 자동 생성은 추가하지 않았다. 기존 STEP 내보내기와 재가져오기 회귀는 유지한다. 실제 제품 치수·문서 정확성, 사내 Windows/오프라인 실행, iPad 조작은 이 환경에서 검증하지 않았다.
