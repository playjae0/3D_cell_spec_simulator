# v1.4 편집·검사·비교 통합 명세

2026-11-18 KST. 전체 앱 main `4df91c9efdb2db4bf3c001ee6c1ef02cf1524837` (PR #4)에서 이어서 구현했다. 요청 ZIP의 `02_SCOPE_AND_ACCEPTANCE.md` A–E가 범위다. 기존 적층/중심 집속/양·음극 독립/7공정 CAD, 직접 편집, 요청 큐와 입력 출처를 유지한다. 신규 파우치 형상, 실링바, EXE/설치 프로그램 및 배포 갱신은 포함하지 않는다.

## A. 리드 실런트

리드 실런트 `positive.leadFilm` / `negative.leadFilm`은 노란 용접부 테이프와 별도 부품이다. S3 메인 용접부터 존재 설정에 따라 생성한다. S0–S2에서는 생성하지 않으며 S2의 리드 포함 선택으로 실런트 부착을 추정하지 않는다. 공정 변환은 복사한 데이터만 사용한다. 기존 가정 단면을 재사용하며 제품 단면이 확정되었다는 뜻은 아니다.

`cad/process.py`, CAD 참조, fields/bindings, intake 계약·사전·조건표·양식이 같은 시점을 사용한다. 실제 CAD 폭 양끝 참조를 추가했다. 테이프 숨김은 실런트에 영향을 주지 않는다. 양극 집속부 집중 보기는 실런트를 유지하며, 사용자가 이미 숨긴 부품을 강제 표시하지 않는다. 전체 셀 보기로 집중 전 숨김·카메라를 복원한다. 명시적인 모두 보기 명령만 전체 숨김을 해제한다.

신규 입력은 `pouch-cell-intake/1.1`, 사전 `cell-intake-1.1`을 사용한다. S3 실런트 존재/부재를 확인하고 존재하면 필요한 치수를 입력한다. 구버전 1.0의 S3에서 실런트 존재와 수치가 모두 미확정이면 null을 유지하고 경고와 함께 해당 부품을 만들지 않는 호환 경로를 제공한다. 이것은 부재 확정이 아니다. 기존 1.0 양식은 보존하고 새 1.1 양식은 generator로 생성한다. 값이 없다고 예시값을 섞지 않는다.

## B. 검사 의미와 개정

`src/annotations/semantics.js`가 검사 의미를 정의한다. 제품 형상, itemId/공정/측정 방식/축/참조/데이텀/목표/공차/측정 조건, 참조 데이텀 원점·회전, 앵커의 부착 대상·위치 규칙이 포함된다. 기존 설명과 분리된 `conditions`에 실제 측정 조건을 기록한다. 구버전 설명에서 조건을 자동 추출하지 않는다.

실측 추가 시 현재 작업과 저장 개정의 검사 의미가 달라지면 새 개정 저장으로 안내한다. 현재 열린 공정의 항목만 실측 UI에 나온다. 샘플에 공정과 mm 단위를 보존한다. 카메라·표시·치수선 배치·설명 문구 변경만으로 새 검사 개정을 강제하지 않는다. 같은 itemId를 서로 다른 공정 기준으로 재사용하지 않고 공정별 독립 ID를 쓴다.

개정 차이는 입력 숫자뿐 아니라 데이텀/앵커/검사 항목/부품 존재/출처를 포함한다. 값, 정의, 출처, 설명, 표시, 추가/삭제를 구분한다. ID가 있는 배열과 객체의 순서만 달라진 경우 변화로 취급하지 않는다. 이력에 저장된 개정과 실측은 수정하지 않는다.

## C. 측정과 검사 보기

치수·스펙에서 대상 A/B → 측정 방식 → 프레임·축 → 위치 → 이름·목표·공차·조건을 선택한다. 선택한 검사 또는 작성 중 검사에 관련 부품, 시작·끝점, 방향 화살표와 실제 검사 프레임 설명을 연결한다. 입력 focus/hover 및 3D 선택/직접 편집 흐름은 유지한다.

거리 x/y/z는 양수 투영 거리다. signed_coordinate는 검사 원점→A의 부호 좌표, signed_offset은 A→B의 부호 차이다. 두께·반경은 기존 analytic CAD 참조를 사용한다. 메시 삼각형이나 화면 픽셀로 검사값을 계산하지 않는다.

등록된 평탄 패치에 고정 mm(중심/모서리 기준) 또는 상대 위치 % 측정점을 생성한다. 고정 mm는 부품 크기가 바뀌어도 기준에서의 거리를 유지하고, 비율은 부품 크기를 따라간다. 곡면·실루엣 임의 스냅은 지원하지 않는다. 참조 소실, 해당 공정에 없음, 패치 범위 이탈, 미확정 부품을 구분하며 재연결/보정을 하지 않는다.

현재 공정 기본 측정 세트는 사용자의 추가 명령으로만 생성한다. 실제 유효한 CAD 참조가 있는 적층체·각 극의 탭/리드/겹침/접합/테이프/실런트 개소를 사용한다. 기존 동일 기준·모드·프레임 항목은 중복 추가하지 않는다. 정확한 참조가 없는 개소는 생성하지 않고 미지원 후보로 안내한다. 생성 항목의 목표·공차는 null이다. 공정 전환으로 검사를 몰래 추가하지 않는다.

검사 보기 프리셋은 이름, 소유 모델/개정/공정, 카메라, 단면, 숨김, 치수 표시, 선택 프레임/검사/부품을 저장한다. 현재 작업에 저장 후 셀 JSON 또는 새 개정에 포함해 보관한다. 다른 모델/개정에서도 참조를 모두 확인한 뒤에만 적용하며, 공정이나 부품/검사/프레임 참조가 없으면 원인을 표시한다. 프리셋은 최대 100개다. 치수 저장 20,000개, 동시에 그리는 치수선 200개 및 목록 50개 단위 제한은 기존과 같다.

## D. A/B 공정·개정 비교

상단 공정·개정 비교에서 각 측의 현재 작업 스냅샷 또는 저장 개정과 공정을 선택한다. 독립 CAD 두 개 계산으로 별도의 형상을 얻는다. 비교는 원본 product/stage/history/선택/카메라를 바꾸지 않는다. 카메라와 단면을 동기화하며 전역 프레임을 그대로 사용한다. 수납/위치 차이를 자동 정렬로 숨기지 않는다.

- CAD 계산 치수 표: mm, Δ=B−A, 각 측 목표·공차, 비교 가능 여부. 각 개정의 저장 프레임이 다르면 직접 비교 불가다. 공통 전역 기준을 선택하면 같은 위치/모드의 값만 다시 계산한다. 다른 앵커 위치 규칙이나 측정 조건까지 같다고 가정하지 않는다.
- 부품 표: 공정 부재, 참조 소실, 존재, 정확한 CAD 외곽 XYZ 및 체적 차이. 외곽/체적 동일이 형상 전체 동일을 증명하는 것은 아니다.
- 입력/검사 정의/출처/표시 차이: 계산 치수와 별도로 표시하고 항목 클릭으로 관련 부품·검사를 강조한다.

비교 전용 직렬 요청과 취소 세대 번호를 사용하며 활성 작업의 CAD 큐를 재사용하거나 덮어쓰지 않는다. product+stage 기준 최대 8개 결과를 캐시하고 카메라 이동 때 재계산하지 않는다. 누락된 다른 공정의 입력은 검사 오류로 남기며 보충하지 않는다. 비교 결과를 활성 모델로 적용하는 기능은 없다.

## E. 파일 병합과 복구

셀 JSON은 현재 셀, 입력 JSON은 출처가 포함된 작성/검토 양식, 보관함 백업은 모델별 모든 개정·샘플·초안이다. 각각의 버튼에서 구분한다.

기존 보관함이 있어도 백업을 읽고 검토할 수 있다. 적용 전에 추가/중복/충돌 요약을 표시한다. 같은 ID와 내용은 건너뛰고 새 모델/개정은 추가한다. 같은 ID의 다른 내용은 명시적인 건너뛰기, 새 모델 복사 또는 새 개정 가지 복사를 선택한다. 새 ID나 접미사를 입력할 수 있다. 복사는 부모·샘플·프리셋 소유 참조도 함께 매핑한다. 샘플/초안 충돌은 별도 건너뛰기 또는 새 ID/개정으로 보존한다. 초안 복사의 입력칸은 새 개정명이다. 샘플/초안만 있는 보관함도 검사한다.

개정 부모 누락/순환, 샘플 연결 오류는 가져오기를 차단한다. 자동 덮어쓰기는 없다. 적용 시 현재 보관함에 대해 다시 검토하고 저장에 성공한 후보만 메모리에 반영한다. 취소·파일 읽기 지연·저장 용량 실패는 기존 목록을 보존한다.

손상된 localStorage는 원본 문자열을 유지하고 쓰기를 잠근다. 원본 다운로드, 복구 백업 목록을 제공한다. 사용자가 복구 초기화를 선택하면 별도 recovery 키에 원본 저장을 먼저 성공시킨 뒤 새 보관함을 만든다. 백업 저장조차 실패하면 초기화하지 않는다. localStorage는 해당 브라우저/주소 전용이므로 사내 운영에서는 정기적으로 보관함 파일을 내보내야 한다.

## 실행 및 수정

기존 Node.js 22.12+ / Python 3.12 64-bit / CadQuery 2.7.0 / Chrome·Edge 환경을 사용한다. Docker 불필요. 의존성 설치에는 패키지 또는 사내 미러가 필요하지만 정상 실행에는 외부 API/CDN이 필요하지 않다. 명령은 README 실행 절을 따른다. Windows 실기는 별도 확인 대상이다. 이 작업의 개발 검증 주소는 `http://127.0.0.1:8768`이며 배포물이 아니다.

계약 수정 후 `node scripts/generate-intake.mjs`, JS/CAD 검사 및 개발 웹 빌드를 실행한다. 변경 파일과 실제 검증 범위는 [검증 기록](validation-integrated.md)에 있다. 물리적 포일 변형, 실링 압축, 새 파우치 배치, 2D 도면/PMI는 구현하지 않았다. 기존 STEP 기능은 유지하며 신규 STEP 기능은 추가하지 않았다.
