# 파우치 셀 구현 기준 v1.1

2026-11-17. 기준: 사용자 ZIP v1.1 + 작업 중 사용자의 **중앙 집속 정정**. 이 문서는 실제 구현 상태와 한계를 기록한다.

## 확정 / 가정 / 미지원

확정: 낱장 전극 적층, 파우치, 양끝 탭/리드, 양극·음극 독립, 탭 용접 후 사진의 노란 띠는 테이프. 주요 상태는 assembly/packaged/finished. V자 접힌 판·블레이드·특수 가이드를 사용하지 않는다.

예시 설정: positive=-X, negative=+X, 리드가 탭의 하면에 접촉, 집속 후 단면의 작은 원호, 리드 실링 필름, 테이프의 선택적 양쪽 모서리 감쌈, 상/하 독립 포켓, 패키징 외장 추가 여유, 완제품 긴 변 접힘. 사진의 보이지 않는 뒷면을 대칭 복제해 확정하지 않는다. 반대 극은 별도의 데이터 객체와 값이다.

미지원: tab_to_tab 별도 예비접합 형상, 실제 용접 패턴/비드/눌림/용입, 임의 측벽 경사, 깊이 0인 평판 한쪽 외장, 자유 곡면 테이프, 임의 BRep 편집, 실제 실링 압축/단차·리드 통과부 국부 성형, 포일/필름의 물리 성형 해석, 정확한 주름, 임의 STEP 업로드·편집, 자동 도면/PMI. 미지원 조건을 조용히 다른 형상으로 바꾸지 않는다.

## 기술 결정

Three.js ES modules + 로컬 Python CadQuery 2.7/OCC 7.8.1 + 버전 JSON을 채택했다. JavaScript를 선택해 사내 Copilot에서 모듈별 수정이 가능하도록 했고 런타임/파일 유효성 검사와 핵심 회귀 검증을 추가했다. TypeScript 도입은 필수 조건이 아니므로 이번 범위에서는 사용하지 않았다.

CAD 선택 근거는 라이브러리 설명이 아니라 실행된 A/B/C proof다. 집속 BRep, 호스트 접촉 테이프, 독립 원호와 내외면을 가진 포켓이 유효한 솔리드로 만들어졌고 STEP 왕복도 통과했다. 브라우저 WASM 커널보다 설치 부담은 크지만 현재 포켓 단면·오프셋·STEP를 검증할 수 있었다. Python 설치가 사내에서 허용되는지는 아직 검증하지 않았다.

원본은 JSON 입력과 `cad/model.py`/`cad/proof_pocket.py`의 생성 규칙이다. 표시용 삼각 메시와 클리핑은 파생 결과다. 치수는 CAD와 같은 해석적 기준 registry에서 계산한다. 메시 삼각형 번호/픽셀 길이를 제조 치수로 저장하지 않는다.

## 좌표와 관계

단위 mm. A: Z=0 조립체 두께 중앙. B: Y=0 폭 중앙. C: X=0 길이 중앙. 별도 검사 datumSet은 원점 XYZ와 Z축 회전을 가지며 형상을 움직이지 않고 측정 축을 바꾼다. 완전한 6자유도 검사 프레임은 미지원이다.

|대상|기준/독립 입력|계산·연결|
|---|---|---|
|조립체|길이/폭/두께/XY R|중심 기준 외곽, 탭 뿌리는 ±L/2에 붙음|
|탭 뿌리|rootWidth, rootSpread, rootY/Z|조립체 폭/두께 범위 검사|
|집속|gatherDistance/Y/Z, width/thickness/length|전이 s(u)=3u²−2u³; 포락 단면 9개를 CAD loft로 연결; 점으로 수렴하지 않음|
|리드|집속점 상대 start, length/width/thickness, offsetY, contactSide|Z는 집속 두께와 접촉면에서 계산; 한쪽 편집이 반대쪽을 변경하지 않음|
|겹침|탭·리드의 실제 X/Y 구간 교집합|접합 관리 영역보다 클 수 있음|
|접합 영역|start/length/width/offsetY, process metadata|실제 교집합 안에 있어야 함. 실제 면은 접촉면; 화면에는 별도 상면 투영 경계로 표시(재료 비드 아님)|
|테이프|host=tab, face=top/bottom, top/top_edges, start/length/thickness|top은 평탄부 폭/위치 입력; top_edges는 탭 폭과 R로 피복 폭 계산, edgeDrop만 추가. 미사용 필드는 비활성|
|리드 필름|집속점 상대 시작, 길이, Y 여유, 두께|리드 외면의 감싸는 셸. 예시이며 실제 단면 확인 필요|
|파우치|개구 L/W, XY R, 각 상/하 깊이·바닥 R·상단 R, 필름 두께|내부 공간과 정확 원호 단면의 offset 외면. 포켓 바닥 크기는 계산값|
|외곽/실링|성형–실링 간격, 실링 폭, 절단 여유|성형/실링 시작·끝/절단 경계를 각각 registry에 등록|
|패키징 여유|추가 −Y/+Y 외장 길이|사진의 이어진 외장 참고. 용도 미확정; 완성 상태에서 제거는 가정|
|완제품 접힘|각도/R, 절단 여유|호 길이 Rθ를 소비하고 남은 직선을 회전. 길이 보존; 단순 축소 아님. 긴 변만, 양끝 릴리프 있는 예시|

리드 접촉면과 테이프 부착면은 독립 입력이다. 리드가 위에 놓였는데 테이프도 같은 접촉 구간의 상면에 있으면 충돌 오류를 내고, 사용자가 노출 면을 선택해야 한다. 자동으로 반대 면에 옮기지 않는다.

리드 전체 길이와 외장 끝에서의 돌출 길이를 혼동하지 않는다. 돌출 길이는 해당 공정의 `pouch.trim.x.*`와 `*.lead.end`를 X 투영으로 측정한다. 표면 두 점 직선 거리를 두께라고 부르지 않는다. Z 두께 모드는 같은 부품의 서로 반대인 상·하면 기준과 같은 XY 위치만 허용한다.

## 포켓 정의와 구현 범위

내면 개구 L/W와 바닥 R=rf, 상단 R=rt로 바닥 평탄부는 `L−2(rf+rt)`, `W−2(rf+rt)`이다. 수직 측벽 길이는 `depth−rf−rt`. XY 바닥 경로 R은 `planR−rf−rt`. 측벽 경사 0인 현재 프로파일에서 깊이>rf+rt, planR>rf+rt, rt>filmThickness가 필요하다.

내면의 바닥 원호와 상단 원호는 반대 곡률이다. 외면은 바닥 R을 t만큼 늘리고 상단 R을 t만큼 줄여 일정 법선 두께를 유지한다. 단면을 둥근 사각 경로로 sweep하고 평탄 바닥과 연결한다. 일반 CAD 필렛의 임의 모서리 번호에 의존하지 않는다.

상/하 필름은 공칭 모델에서 A에 맞닿는다. 리드 통과부는 아직 국부 성형되지 않았으므로 간섭 없는 실링 조립체로 보증하지 않는다. 화면 진단과 최종 보고에 이 제한을 명시한다. 실제 치수 적용 전 이 부분의 단면 모델 확장이 필요하다.

## 치수·기준점·저장

등록 기준은 점/모서리 중점/면 중심/반경이다. Raycaster로 부품을 선택하고 의미 있는 기준으로 스냅한다. 자유 표면점은 리드와 조립체 상·하면 평탄부에서만 지원한다. `anchor.id + baseFeatureId + u/v`를 저장하며 조립체 코너 R에 의해 점이 잘리거나 호스트가 사라지면 무효 처리한다. 임의 곡면 클릭을 지원하는 척하지 않는다.

치수는 id/name/group/stage/mode/a/b/offsetAxis/offset/visible/spec를 갖는다. 목표값과 ±공차 크기, 실측값, 설명을 분리한다. 계산값은 매번 참조에서 얻는다. 실측값은 형상을 변형하지 않는다. 등록된 치수마다 가시성을 보관한다. 공정별 필터, 그룹 토글, 검색, 전체 표시/숨김을 지원한다.

JSON schemaVersion=2, modelVersion=pouch-datum-cad-1. 제품, 독립 극 객체, 기준점, 치수, 스펙, 데이텀, 카메라/숨김/단면/투명 상태를 저장한다. v0.4 파일은 측정 기준이 달라 자동 추정 변환하지 않는다. 무효 참조는 경고와 카드 오류를 표시하며 다른 면에 자동 연결하지 않는다. 재연결 버튼은 사용자가 위에서 선택한 A/B를 명시적으로 적용한다.

## 상태 처리

입력 초안과 마지막 정상 project를 분리한다. 적용 시 현재 form 값을 수집→스키마 검증→서버 CAD 유효성 검사→revision 확인→registry/메시/치수 갱신. 실패하면 초안과 원인을 남기고 정상 형상을 유지한다. 미적용 상태에서는 저장/STEP를 비활성화한다. 늦게 도착한 이전 revision은 적용하지 않는다. 설계 undo/redo는 30개 스냅샷이며 텍스트 편집 전체의 범용 undo는 아니다.

POST /api/rebuild는 project+revision을 받으며 geometryId, parts, semantic features, paths, diagnostics를 돌려준다. 서버는 파라미터+상태별 8개 캐시와 OCC 직렬 lock을 사용한다. POST /api/step는 관리 영역 face를 제외한 솔리드를 STEP mm로 내보낸다. 임의 외부 경로/URL을 읽는 API가 없고 127.0.0.1에만 바인딩한다.

## 기존 코드와 보존

기존 main의 v0.4(PR #1 merge 592bb51)를 확인하고 실제 화면을 실행했다. 공통 리드 치수, 떠 있는 테이프 판, 실체 상자 파우치, 무차별 부품 제거가 새 명세와 충돌했다. 기존 형상 생성부는 재사용하지 않았다. Three.js/OrbitControls와 mm 단위 인터페이스 패턴만 계승했다. 기존 로컬 `/workspace/cell`은 수정하지 않았고 새 프로젝트에서 작업했다. 이전 문서는 docs/legacy-v0.4에 보관했다.
