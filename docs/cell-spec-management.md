# 파우치 셀 제조 스펙 관리 기준
버전 v0.3 기반 저장소 정리본 / 2026-11-17
상태: 요구사항 및 구현 명세 초안. 앱 구현 및 CAD 검증 미수행.

## 목적과 적용 범위
파우치 셀과 공정별 반제품을 회전·확대하며 제조 스펙, 측정 기준, 공정 조건을 설명하고 관리한다. 공개 저장소에서는 가상 형상과 예시 데이터만 사용한다. 실제 치수와 사내 스펙은 사내 운영본에서 관리한다.
사용자가 제공한 v0.3을 기준으로 정리했다. 사진 원본은 이번 작업에 제공되지 않았으며 아래 사진 관찰 사항은 사용자 문서의 기록이다. 실제 제품 형상 검증을 의미하지 않는다.

## 좌표 및 치수 정의 제안
아래는 구현 검토를 위한 제안이며 제조 기준 확정값이 아니다.
기본 단위 mm, 우수 좌표계, 몸체 중심 원점, X 길이·Y 폭·Z 두께로 한다. 부품 ID는 시점에 독립적이며 leadA/leadB와 polarity 속성을 분리한다. 극성 미확인 값은 unknown이다.

|변수|정의|
|---|---|
|body.length / width / thickness|S3 외장 몸체의 축별 최대 범위. 돌출 리드 제외|
|body.planarRadius|XY 평면 외곽 반경. 두께 방향 전이 반경과 별개|
|leadA/B.protrusion|해당 외장 몸체 끝 기준면에서 리드 끝까지 X 방향 거리|
|leadA/B.width / thickness|리드의 Y/Z 방향 범위|
|leadA/B.offsetY / offsetZ|몸체 중심 좌표계 기준 리드 중심 위치|
|jellyroll.length / width / thickness|S1 몸체 기준 범위|
|tape.positionX / widthY / lengthX / thicknessZ|젤리롤 기준 테이프 위치와 축별 크기|
|weld.positionX / widthY / lengthX|사용자 지정 예시 용접 영역. 실제 유효 용접부 판정과 별개|
|pouch.formingDepth / flangeWidth|성형 깊이와 외곽 여유 폭|
|seal.effectiveWidth|사용자 지정 실링 유효 폭. 외곽 여유 폭과 별개|

리드와 탭 묶음은 별도 부품으로 연결 관계를 기록한다. 테이프·용접 영역은 개별 선택·설명 대상이다. 숨기기·투명화 상태에서도 선택 대상 부품을 명시한다.
설계 치수(형상 구동), 표시 치수(형상에서 계산), 제조·검사 스펙, 측정값을 분리한다. 설계값 변경이 측정값을 덮어쓰지 않는다.
두 점 P,Q의 직선 거리는 sqrt(dx²+dy²+dz²), 축 투영 치수는 |dx|, |dy|, |dz|이다. 방향성이 필요한 경우 부호 있는 변위를 별도 저장한다.
두께는 두 표면 점의 임의 거리와 다르다. 기준 위치·측정 방향·대응 면·측정 조건을 함께 지정한다. 측정값으로 표면을 변형하는 보간·경계 조건은 미정이다.
음수·0 크기, 비유한 숫자, 과도한 반경, 부품 충돌을 검증한다. 평면 반경은 min(length,width)/2 이하이다. 공정상 의도한 접촉과 비정상 충돌을 구분할 규칙은 추가 정의한다.

## 참조와 저장 데이터
schemaVersion과 modelVersion을 둔다. 제품·공정·부품 ID, 단위·좌표계, 형상 변수, 부품 연결, 스펙, 측정값, 주석, 카메라·표시 상태·설명 장면을 저장한다.
참조는 partId + featureId + 정규화 위치 또는 기준으로부터 거리로 구성한다. 임의 면 번호나 월드 좌표만으로 연결을 유지하지 않는다. 자유 점도 선택 당시 부품과 위치 해석 방법을 기록한다.
치수에는 id, stageId, kind(distance/projected), axis, startRef, endRef, lineOffset, label, description을 포함한다.
스펙에는 명칭, 목표값, 상·하한 또는 공차, 단위, 적용 공정, 측정 기준 ID, 설명을 포함한다.
측정 기록에는 위치 참조, 방향, 값, 단위, 필요 시 측정 조건을 포함한다.
참조 소멸 시 invalid로 표시하고 값을 정상 치수처럼 제시하지 않는다. 다른 면으로 자동 연결하지 않고 재선택을 요청한다. 공정에서 숨긴 부품과 모델에서 삭제된 부품은 구분한다.
저장 형식 변경 시 마이그레이션을 제공하거나 지원하지 않는 버전을 명시적으로 거부한다. 잘못된 파일은 현재 장면을 변경하기 전에 검증한다.

## 구현 구조와 실행 제안
브라우저 웹 앱을 기본 후보로 한다. HTML 진입점과 TypeScript 또는 JavaScript 모듈, CSS, JSON, 패키지 설정·고정 파일로 구성한다. Three.js는 표시·선택 후보이며 아직 기술 선택이 확정되지 않았다.
- src/viewer: 렌더링·카메라·선택
- src/geometry: 형상 생성·종속 관계
- src/annotations: 기준점·치수·설명
- src/data: 저장·복원·버전 처리
- examples: 가상 제품과 예시 스펙
- docs: 기준 문서·실행·인계 안내
- tests: 형상·계산·참조·저장 회귀 검증

정확한 CAD 라운드·모따기와 STEP은 별도 커널 검증이 필요하다. 브라우저 WASM 또는 PC 로컬 CAD 서비스 중 설치 가능 범위와 성능으로 결정한다. STEP와 편집 규칙·주석 JSON을 함께 관리하며 STEP 주석 교환은 미정이다.
1차는 PC 로컬 서버 실행을 제안한다. 단일 HTML 더블클릭은 모듈·CAD 실행 제약을 확인한다. 외부 의존 파일을 배포물에 포함하고 네트워크를 차단한 상태로 실행 검증한다. 다수 사용자 운영은 요구 확인 후 검토한다.

## 개발 순서와 검증
1. 조작과 치수: 가상 셀·반제품, 회전·확대·이동, 선택, 기준점, 두 점 치수, 저장·재열기.
2. 파라메트릭 형상: 기본 치수·평면 반경·정의한 모따기, 주석 갱신. 별도 작은 예제로 CAD 로컬 실행·반경·STEP 내보내기 검증.
3. 공정 스펙: 세 공정, 영역별 설명, 입력 화면, 설명 장면, 데이터 형식 확정.
4. 위치별 두께 및 인계: 측정점 표현, 배포물, 실행 안내, Copilot 문맥과 회귀 사례.

첫 구현 목표는 양끝 리드, 세 공정 상태, 테이프·용접 선택, 기본 치수 편집, 회전·확대·이동, 앞·뒤·측면 보기, 두 점 직선·축 투영 치수, 치수선 배치, JSON 저장·복원이다.
가상 테스트에서 몸체 길이 200 mm는 200 mm로 계산되어야 한다. 리드 돌출 20→30 mm 변경 시 해당 표시 치수도 갱신되어야 한다. 이 수치는 테스트용이며 사진 추정값이 아니다.
추가 완료 증거: 회전·확대 후 동일 참조 선택, 무효 참조 경고, 저장 후 형상·공정·설명·치수·카메라 복원. 실제 사내 브라우저·오프라인 환경 검증은 별도 수행한다.
CAD 채택 시 STEP 재가져오기 후 기준 치수와 형상 비교를 수행한다. 사진 유사성은 계산 정확성의 증거가 아니다.

## 인계와 미정 사항
인계물은 소스, 가상 데이터, 실행 안내, 기준 정의, 미구현 목록, 검증 결과 및 기준 커밋으로 구성한다. Copilot 수정 시 실제 스펙 외부 반출 없이 사내 운영본에서 작업한다.
결정 필요: 우선 편집 변수의 종속 관계, 최초 측정 사례 2~3개의 정확한 시작·끝, 내부 구성과 극성, S2 실링 기준, 사내 브라우저·로컬 서버·패키지 설치 가능 여부, STEP 가져오기/내보내기 우선순위, 공동 편집·서버 필요성.
주름 전체의 파라메트릭 재현과 임의 형상 편집 범위는 미정이다.
