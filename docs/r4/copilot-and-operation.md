# R4 조작과 사내 입력

기준: main 84d608a + 이번 R4 변경. 숫자는 전부 가상 예시 mm이며 제조 표준을 의미하지 않는다.

## 실행

기존 실행 경로를 사용한다. Windows는 저장소 루트에서 `scripts/setup.ps1` (최초 의존성 설치), `scripts/start.ps1`. Python/CadQuery와 Node.js가 필요하고 Docker는 필수가 아니다. 이미 설치된 환경에서는 `npm run build` 후 `python cad/server.py`로 실행하고 `http://127.0.0.1:8765`에 접속한다. 포트 변경은 Windows PowerShell에서 `$env:POUCH_PORT=8772; python cad/server.py`, Linux에서 `POUCH_PORT=8772 python cad/server.py`. 실행 중 외부 API/CDN은 필요하지 않다. 초기 의존성 설치는 네트워크 또는 사내 패키지 저장소가 필요하다. 이번 회차에는 설치파일을 빌드하지 않았다.

## 어디서 조작하는가

오른쪽 **요소기술 → R4 가상 예제 열기**로 시작한다. 기존 셀을 열어도 R4 예시값을 자동으로 넣지 않는다. 요소기술의 기본 화면은 혼·엔빌 작업면 평면도이며, 보조로 대표 치형 단면을 제공한다.

- **혼·엔빌 작업면**: 극, 가용접/메인 공정, 혼/엔빌을 각각 선택. 외곽과 너링 범위, 피치/방향/높이/치형, 배치, 공구 개정은 독립 입력. `선택 공구만 +½ U 피치 이동`으로 대응 접촉 위치를 확인한다. 실물 치형 전체의 압흔 해석이 아니라 작업면 범위와 대표 치형이다.
- **가용접 포일 집속**: 상면 기준 깊이를 입력. 결과 표에 진입 중심 Z, 잔류 두께, 상하 할선 경사, 고정 하면·뿌리·진입 X·폭을 표시한다. S2부터 후공정은 이 설계값을 참조한다. 기존 S1은 용접 전 집속 상태다.
- **레이저 스팟**: 극별 메인 방식을 레이저로 선택하고 S3 미리보기. 배열 행열·피치·회전 및 스팟별 dx/dy. 각 점의 펼침 영역에서 이동/삭제한다. 추가는 새 ID를 만들고 삭제는 남은 ID를 바꾸지 않는다. 원주 이탈을 빨간색과 문구로 표시한다.
- **실링바 평면 윤곽**: 위치(양극/음극/가스방/최종), 상하 바를 선택. U–V 윤곽점과 원호 처짐을 편집한다. `arc`는 직전 점에서 해당 점으로 가는 현의 왼쪽 방향 처짐이며 0은 직선이다. 반대쪽 외곽점은 독립이다. 상하 유효 중첩을 계산하므로 한 바만 밖으로 확장하면 다른 바가 폭을 제한할 수 있다. 제품 영역은 두 바의 중첩과 실제 남은 필름의 교집합이다. 기본 타격과 추가 타격의 합집합을 별도 표시한다. 홈은 선택 U의 국부 단면으로 표시하고, 깊이가 있는 홈의 투영 띠를 공칭 접촉면에서 제외한다. 열융착이나 압력 분포를 예측하지 않는다.
- **한 장 필름·가스방**: R0 열린 두 컵, R1 수납, R2 닫힘, R3 탭측 실링/가스측 개구, R4 외곽 실링/몸체 연통, R5 최종 실링/격리, R6 가스방 절단, R7 잔여 플랜지 폴딩. 각 단계 버튼은 미리보기이며 **적용**하면 위쪽 공정 선택과 확정 형상이 바뀐다. 컵 크기/R 및 입구 X/Y, 브리지 R, 절단선, 폴딩을 편집한다. 가스/최종 실링선의 위치는 실링바에서 한 번 입력한다.

**CAD 미리보기 → 취소 또는 적용 → 셀 JSON 저장 → 불러오기**. 미리보기 중에는 저장을 막고, 선택/관리 치수 추가는 확정 형상에서 수행한다. 공정 전환은 같은 설계의 다른 상태를 재생성한다. 절단 후에도 원래 실링바 스냅샷을 지우지 않으므로 앞 공정으로 돌아가 같은 기록을 재현한다.

왼쪽 **CAD 계산 / 관리 치수 추가**에서 실링 폭, 포일 잔류 두께, 컵 깊이 등을 치수·스펙으로 추가한다. 기존 **치수·스펙**에서 목표/공차/설명/실측을 관리하며 설계값과 실측은 분리된다. 항목 hover/선택은 부품과 두 기준을 강조한다. 부품 숨김·투명·내부 선택과 단면은 기존 하단 도구를 사용한다.

## 사내 명칭과 Copilot 인수

`fields-and-company-names.json`은 실행 데이터에서 생성한 신규 ID·값·단위·공정·극·데이텀 목록이다. `companyName`, `sourceDocument`, `reviewStatus`를 채운다. `id`는 스팟/윤곽점의 안정적인 ID를 사용하고 `adapterPath`는 현재 배열 위치다. 배열 순서로 장기 참조를 저장하지 않는다. 화면의 **R4 필드·명칭 양식 내려받기**는 현재 모델 값으로 같은 목록을 만든다.

Copilot 입력 예:

> 이 저장소의 docs/r4/design.md와 fields-and-company-names.json을 읽어라. 첨부 사내 표를 stable id로 연결하고 mm/deg/무차원 단위를 검증해라. 양극·음극, 혼·엔빌, 상하 바를 서로 복사하지 마라. processTooling 스냅샷과 기존 product 값을 함께 버전 관리해라. 미정값을 예시값으로 채우지 말고 미정으로 보고해라. 설계 수정은 CAD 형상/계산값/주석/저장 왕복 테스트로 검증하고, 실측은 검사 항목에만 저장해라.

입력 양식 1.3의 `processTooling`은 프로젝트의 동일 객체와 동기화된다. 공구 ID/개정/적용 공정/극/배치/윤곽/스팟 전체가 모델 개정에 포함된다. 1.0–1.2 입력에 이 객체가 없으면 그대로 유지한다. 가상 예제는 `examples/process-tooling-r4.json`, 대응 입력은 `examples/intake/virtual-tooling-1.3.json`이다.

## 정확도와 범위

OCC 면/교선으로 면적·폭을 계산하고 Three/CPU 메시와 구분한다. 포일은 smoothstep 포락, 브리지는 균일 두께 원통 접힘, 폴딩은 기존 중립 기준층 길이 보존 모델이다. 개별 필름의 체적/변형률 보존, 압력 분포, 열융착, 실제 용접 강도, 가스 팽창은 보장하지 않는다. 리드 통과부의 국부 필름 소성 성형은 미지원이며 평면 실런트 중첩과 공칭 간섭을 별도로 확인해야 한다. 신규 원호가 폴딩 구간을 가로질러 기존 접힘 커널의 지원 범위를 벗어나면 원인을 표시하고 거절한다.

Windows 실장비·GPU·완전한 사내 오프라인 환경은 이 Linux/CPU 검증과 별도로 인수 확인한다. STEP 엔진은 기존 기능을 유지하지만 R4 STEP 교환은 이번 완료 기준에 포함하지 않았다.
